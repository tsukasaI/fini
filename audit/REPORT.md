### 3.1 バグ・潜在的バグ

#### B-01 ファイルを直接指定すると除外パターンが適用されない
- 重大度: High / 確信度: 確認済み(8 章。`ef38390` で単体テストと結合テストにより再現)
- 場所: `src/walker.rs:64`、`src/walker.rs:94-110`
- 内容: `--exclude` と `fini.toml` の `exclude` は、ディレクトリを走査して見つけたファイルにだけ効きます。引数で直接指定したファイルには効きません。README が案内する pre-commit フック(`types: [text]` でファイル名を渡す)と Claude Code フック(編集したファイル 1 件を渡す)はどちらも直接指定なので、`exclude = ["vendor/"]` と書いても `vendor/` 配下が書き換えられます。
- 根拠: 走査に使っている `ignore` クレート 0.4.33 の `walk.rs:1149-1152` は、起点そのもの(深さ 0)を無条件で通します。
  ```rust
  fn skip_entry(&self, ent: &DirEntry) -> Result<bool, Error> {
      if ent.depth() == 0 {
          return Ok(false);
      }
  ```
  fini 側は除外パターンをこの仕組み(`builder.overrides(...)`)に渡しているだけで、起点への独自チェックはありません。除外の結合テスト(`tests/integration.rs:979`、`:998`、`:1019`)はディレクトリ指定のみです。
- 再現手順(未実行、コードからの予測):
  ```console
  $ mkdir -p t/vendor && printf 'x \n' > t/vendor/a.txt
  $ fini --check --exclude 'vendor/' t                # 除外される
  $ fini --check --exclude 'vendor/' t/vendor/a.txt   # 除外されず、終了コード 1 になるはず
  ```
- 推奨修正: 起点がファイルのときも除外パターンを照合する(走査の起点ごとに `Override::matched` を呼ぶ)。意図的な仕様なら README と `--exclude` のヘルプに明記する。
- issue 突き合わせ: 新規(検索語: exclude / explicit / pre-commit。該当なし)

#### B-02 ゼロ幅文字の除去が絵文字と一部言語の文章を壊す
- 重大度: High / 確信度: 確認済み(8 章。`ef38390` で単体テストと結合テストにより再現)
- 場所: `src/normalize/fix.rs:5-13`、`src/normalize/fix.rs:246-273`、`src/normalize/mod.rs:50`
- 内容: 除去対象に U+200D(ゼロ幅接合子)、U+200C(ゼロ幅非接合子)、U+200E / U+200F(書字方向の指定)が入っており、文脈を見ずにファイル中のすべてを消します。既定で有効です。U+200D は絵文字の合成(技術者、レインボーフラッグ、家族などの絵文字は、複数の絵文字を U+200D でつないだもの)に必須で、U+200C はペルシア語、U+200D はシンハラ語などで綴りの一部です。README、Markdown、翻訳ファイル、テストデータにこれらがあると、修正モードで黙って別の文字列になります。
- 根拠: `remove_zero_width_chars` は `ZERO_WIDTH_CHARS.contains(&ch)` だけで判定しています(先頭の BOM のみ例外)。既存テスト `src/normalize/mod.rs:748` は `"a\u{200D}b\n"` からの除去を固定しており、絵文字や非ラテン文字の例はありません。
- 再現手順(未実行): `printf '\xf0\x9f\x91\xa8\xe2\x80\x8d\xf0\x9f\x92\xbb\n' > e.md && fini e.md` を実行すると、1 文字だった技術者の絵文字が「男性」と「パソコン」の 2 文字に分かれるはずです。
- 補足(状況証拠): このレポートの初稿には結合絵文字を直接書きましたが、ファイル書き込み後に自動で走るフックが内容を整形した後、U+200D は 0 件になっていました(`rg -c` で確認)。そのフックが fini かどうか、初稿に U+200D が確かに入っていたかは確認できていません。そのため本文では絵文字を文字で説明しています。
- 推奨修正: 既定の除去対象を U+200B、U+2060、ファイル途中の U+FEFF に絞り、U+200C / U+200D / U+200E / U+200F は別オプションにする。少なくとも README に影響を明記する。仕様として維持するかどうかは判断が必要です。
- issue 突き合わせ: 新規(検索語: emoji / ZWJ / Persian。該当なし)

#### B-03 複数行の秘密鍵は先頭行しか伏せ字にならない
- 重大度: Medium / 確信度: 確認済み(8.2。実行で再現)
- 場所: `src/normalize/detect.rs:32`、`src/normalize/detect.rs:269-300`、`src/output.rs:449`
- 内容: diff の伏せ字は 1 行単位で、秘密情報のパターンに一致した行だけを置き換えます。PEM 形式の秘密鍵で一致するのは `-----BEGIN ... PRIVATE KEY-----` の行だけなので、鍵の本体(Base64 の行)は伏せ字になりません。鍵ファイルの改行コードが CRLF、または行末に空白がある場合、`--diff` は全行を変更として表示するため、鍵の本体が CI ログに出ます。変更行の前後 3 行の文脈としても表示されます。
- 根拠: `mask_secret_lines` は `content.split_inclusive('\n')` の各行を独立に判定します。`CLAUDE.md` は「all diff paths mask secret-matching lines」と書いており、README は「どのパターンにも一致しない秘密は表示される」とだけ注意しています。検出はされているのに本体が出る点は書かれていません。
- 再現手順(未実行): `BEGIN RSA PRIVATE KEY` の行に続けて、行末に空白を付けたダミーの Base64 行を数行置き、`fini --check --diff <file>` を実行する。
- 推奨修正: `BEGIN ... PRIVATE KEY` から対応する `END` 行までをまとめて伏せ字にする(`END` が無ければファイル末尾まで)。
- issue 突き合わせ: 関連(#44、#156 はいずれも解決済みで、行単位の伏せ字が前提。複数行は範囲外)。新規 issue を提案。

#### B-04 秘密情報のパターンが一般的な書き方を取りこぼす
- 重大度: Medium / 確信度: 確認済み(8.2。`DSA`、`ENCRYPTED`、`ghu_`、`ghs_`、`ghr_` は読解のみ)
- 場所: `src/normalize/detect.rs:29-73`
- 内容: 正規表現を読む限り、次の形は検出されません。
  - JSON や Python の辞書のようにキーを引用符で囲む形: `"password": "hunter2hunter2"`(キー名の直後に `=` か `:` を要求しているため、閉じ引用符で不一致)
  - 値に引用符がない形: YAML の `password: hunter2hunter2`、`.env` の `API_KEY=abcd1234efgh5678`
  - `OPENSSH` / `EC` / `DSA` / `ENCRYPTED` の秘密鍵ヘッダー(`RSA` と種類なしのみ対応)
  - GitHub の `gho_` / `ghu_` / `ghs_` / `ghr_` / `github_pat_` で始まるトークン(`ghp_` のみ対応)
  - ラベルなしの AWS アクセスキー ID(`AKIA...` 単体)
  - 値に `=` を含むもの(Base64 のパディングなど)
- 根拠: 「hardcoded secret」の正規表現は `(password|...)\s*[=:]\s*["'][a-zA-Z0-9_\-/+@#$%^&*!~.]{8,}["']` です。検出の単体テスト(`src/normalize/detect.rs:456-723`)に上記の形はありません。
- 影響: README は `.env` を秘密が入りやすい場所として挙げていますが、`.env` の標準的な書き方(引用符なし)は検出できません。検出は補助機能ですが、利用者は CI の関門として使う想定です。
- 推奨修正: キー側の引用符を許容し、引用符なしの値に対応し、鍵ヘッダーとトークン接頭辞を追加する。README に検出できる形とできない形の一覧を載せる。
- issue 突き合わせ: 新規(検索語: github_pat / JSON / unquoted / secret pattern。該当なし)
